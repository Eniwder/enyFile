# D&D実装と検証

## 実装方針

| 方法 | 実装負担・安全性・互換性 |
| --- | --- |
| HWNDのOLE `IDropTarget`から転送先のShell `IDropTarget`へ委譲（採用） | 既存のShellデータオブジェクトと`SHDoDragDrop`を維持できる。コピー・移動の選択、転送元への結果通知、衝突・権限・キャンセル・部分成功をWindows側で扱う。enyFile側に新しいコピー／移動エンジンを追加しない。 |
| Slint／winitのファイルドロップ通知で独自に実行 | Slint側の受付実装に加えて、OLEの操作効果の交渉・修飾キー・ドラッグ元への結果通知が必要。既存のパス転送ワーカーは再利用できるが、非同期転送の成功前にドラッグ元へ移動成功を返さないためのプロトコル管理も増える。 |

`main.rs`でwinitの既定の受付を解除してから、同じHWNDに独自の受付を登録する。Slintは実際のペイン配置に基づくヒット判定と強調表示を担当する。転送は転送先フォルダのShellターゲットへ委譲するため、貼り付けの独自衝突画面を経由せずWindows標準の確認画面になる。既存の貼り付け計画・置換処理は変更していない。

操作効果はドラッグ元が許すコピー・移動の範囲でShellが選ぶ。`DragEnter`／`DragOver`の結果がカーソルへ反映される。[MicrosoftのIDropTarget仕様](https://learn.microsoft.com/en-us/windows/win32/api/oleidl/nf-oleidl-idroptarget-dragenter)を参照。

内部ドラッグは既存の`SHDoDragDrop`実行中だけUIスレッドのスコープで識別する。設定が無効でも外部データは拒否しない。同一プロセスの同一ウィンドウ内を内部ドラッグとして扱い、別プロセスのenyFileからは外部ドロップとして扱う。

同一ペイン内の移動は独立した設定`intra_pane_move`（既定オフ）で許可する。転送先がフォルダ行のアイコン・名前列の場合だけ受付し、通常ファイル・属性列・余白は拒否する。操作効果はMOVEだけに制限し、ShellへのDragEnter／DragOver／Dropも移動指定で一貫させる。Ctrl・Altが指定された場合やドラッグ元がCOPYだけを許す場合は拒否し、コピーや意図しない移動へ代替しない。ファイルIDによる同一場所・自身の配下の検証、枠表示、ホイール、Shellによる転送は既存の共通処理を使う。

COMインターフェイスはすべてウィンドウのOLE STA内で保持・解放する。登録はRAIIで解除し、データオブジェクトは離脱・ドロップで解放する。Shellがメッセージを処理して再入する可能性があるため、Shell呼び出し中はControllerや状態のRefCellの借用を保持しない。

内部ドラッグの開始はSlintタイマーではなく、専用のWindowsメッセージへ遅延する。Slint／winitのアプリケーションコールバックを抜けてからOLEに入ることで、ドラッグ中にもwinitが描画イベントを処理できる。宛先の枠表示・解除は外部／内部で共通の`feedback`を使用し、ホイールによるページ変更も同じネイティブ再描画経路を使う。再描画要求をまとめて専用メッセージに投稿し、その処理内で`RedrawWindow`を呼ぶ。通常のSlintのフレーム制御はタイマーを使うため、OLEのモーダルループ中はそれだけに依存しない。

転送先が変わったときとドロップ直前に既存のファイルID・祖先判定を再利用する。同じ場所・自身の配下・不存在を含むバッチは全体を拒否する。フォルダ行のアイコン・名前列はそのフォルダ（「..」は親）、名前列以外・通常ファイル・余白は表示フォルダが転送先になる。名前列の境界はSlintの実際の列配置から取得し、フォルダ内への転送時だけ名前列を強調する。検索・比較結果、ドライブ行、モーダル画面・メニュー表示中、既存のファイル操作中は拒否する。

座標から得た行番号は、現在ページの`row_count()`の範囲内の場合だけ全体の`slot()`へ変換する。行高で割り切れない下端の余白から次ページの非表示フォルダを参照しない。表示行の外側は余白として扱い、外部・ペイン間では表示フォルダ宛て、同じペイン内では拒否する。

ドラッグ受付中だけ`WH_MOUSE_LL`を登録し、ホイールを既存のページ送り処理へ渡す。フック内ではウィンドウの確認とメッセージの投稿だけを行い、UI・COMを呼ばない。ウィンドウ外の入力は通過させ、離脱・中断・ドロップ時に解除する。世代付きメッセージで終了済みドラッグの入力を無視し、高解像度ホイールの差分はペインごとに蓄積する。Shellの転送ダイアログ中は捕捉しない。[LowLevelMouseProcのスレッド・寿命の仕様](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)を参照。

転送元パスは不変の共有データとして保持し、`DragOver`ごとの全件複製を避ける。フォルダを移る時の後始末とドラッグ全体の終了処理を区別し、開始・継続中のエラーでも転送元データとホイール捕捉を解放する。COM参照の解放は状態の借用を外してから行う。ホイール捕捉の初期化に失敗した場合は診断ログに記録し、通常のドロップ受付は維持する。

ShellにDropを渡した場合は、成功・中断・部分成功・エラーを問わず既存の`Controller::refresh_shown`で一覧を更新する。別ペインの検索結果と読み込み中の状態を維持し、Shellへ渡す前に拒否した場合は余計な再読み込みを行わない。実UI/OLEのスモークは`app/src/dnd/smoke.rs`、単体テストは`app/src/dnd/tests.rs`に分離している。

## 未対応・追加の手動確認

実パスのない仮想ファイル、リンク作成、検索・比較結果へのドロップは未対応。外部への既存のリンク作成能力は変更していない。

以下は自動テストだけでは確認していないため、配布前に専用の一時フォルダで確認する。

| ケース | 手動確認内容 |
| --- | --- |
| Explorerからの実マウス操作 | Explorerからの基本的な実マウス操作はユーザー確認済み。追加: 同一／別ドライブ、Ctrl・Shiftをドラッグ途中で切替、フォルダ行と余白、Escによる中断 |
| 権限拒否 | 実際のACLで書込不可にした一時転送先で、Shellの表示・失敗・昇格確認を確認 |
| D&Dの衝突・転送途中キャンセル・部分成功 | Windows標準画面で確認し、元／先の実ファイルと各ペインの更新を確認。貼り付け経路の自動テストとは区別する |
| UNC・WSL・遅い／切断された共有 | 既存と同じパス変換を使用しているが、実際のネットワーク上のD&Dと待ち時間は未検証 |
| 2～4ペイン・DPI変更 | UIの全レイアウトの既存スモークは成功。実ドラッグでの全レイアウト・混在DPIは追加確認が必要 |

パス検証とShellターゲットへの接続はSTA上で行うため、遅い共有やShell拡張によりドラッグ中に待つ可能性がある。安全判定の後からShell実行までの間に外部プロセスがパスを差し替える競合は完全には排除できない。キャンセルは完了した転送の巻き戻しを保証せず、権限や個々の項目の失敗に関する最終的な判断・表示はShellに従う。

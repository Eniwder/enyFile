## インストールと更新

[Releases](https://github.com/Eniwder/enyFile/releases/latest) の `enyFile-vX.Y.Z-windows-x64.zip` を展開し、`enyfile.exe` を実行する。インストーラーはない。動作環境は Windows 10 / 11（x64）。

設定は `enyfile.exe` と同じフォルダの `config.json` に保存する（ポータブル）。フォルダごと移動・コピーすれば設定も一緒に移る。`Program Files` など書き込めない場所に置くと設定を保存できないので、書き込める場所に展開する。

新しいバージョンに更新するときは、`enyfile.exe` だけを差し替えれば設定はそのまま残る。zip を丸ごと上書きで展開すると、エージェントのメモリ（`agent\memory.md`）が初期内容に戻るので注意。

ダウンロードした zip が Release のものと同じかは、次のどちらかで確かめられる。

- 同じ Release にある `.sha256` の値と、`Get-FileHash enyFile-vX.Y.Z-windows-x64.zip`（PowerShell）または enyFile のプロパティ（Alt+Enter）の SHA-256 を比べる
- [GitHub CLI](https://cli.github.com/) で `gh attestation verify enyFile-vX.Y.Z-windows-x64.zip -R Eniwder/enyFile`（このリポジトリの Release ワークフローがビルドしたことの証明。展開した `enyfile.exe` も同じ方法で確認できる）

`enyfile.exe` にはコード署名がないため、初回の起動時に Windows SmartScreen の「Windows によって PC が保護されました」が出ることがある。その場合は「詳細情報」→「実行」で起動できる。

`config.json` が壊れていて読めないときは、`config.json.broken-日時` に退避して既定の設定で起動する。異常終了したときは、同じフォルダの `crash.log` に記録が残る（不具合の報告に添えてほしい）。

## 操作

| 操作 | 動作 |
| --- | --- |
| Ctrl+C / Ctrl+X | 選択項目をクリップボードへ（Explorerと相互運用）。未選択なら何もしない |
| Ctrl+V | アクティブなペインの表示フォルダへ貼り付け。同名があれば自作の確認画面。同じフォルダなら「- コピー」で複製 |
| Delete / Shift+Delete | ごみ箱へ / 完全削除（確認はWindowsの設定に従う） |
| Enter / ダブルクリック | フォルダを開く / 既定のアプリで開く |
| Alt+↑・Backspace / Alt+← → | 親へ / 戻る・進む |
| Tab | 左右切替（起動時は右のペインがアクティブ） |
| Ctrl+L / F5 / Esc | パス欄（`shell:Desktop`・`shell:Downloads` などのシェルフォルダ名も入力できる。ごみ箱など実体のないフォルダは Explorer で開く。フォルダでないもの（`shell:AppsFolder` のアプリなど）は開かない） / 再読込 / 選択解除（フィルター中はフィルター解除） |
| Ctrl+F / Ctrl+G / Ctrl+Shift+G | アクティブなペインを検索（入力中にカーソルが一致項目へ移動。入力中も Ctrl+G で次へ、Enter か Esc で終了） / 次の一致 / 前の一致。検索・フィルター・フォルダ以下の検索の入力欄は、文字を消しても終わらず、空の状態で Backspace を2回押すと終了（Esc と同じ） |
| Ctrl+Shift+F | アクティブなペインをフィルター（入力中に絞り込む。Enterで確定、空で確定すると解除、Escで開く前のフィルターに戻す）。並べ替え・再読込では保たれ、別のフォルダを開くと解除 |
| Ctrl+Alt+Shift+F | 表示中のフォルダ以下を再帰検索し、結果をアクティブなペインに表示（下の「フォルダ以下の検索」） |
| ← → / PageUp PageDown / ホイール | 前後のページへ（カーソルはページ内の同じ位置）。一覧はスクロールせず1画面ずつ表示。最初のページで ←、最後のページで → は1行ずつ移動し、ホイールはそれ以上めくらない（カーソルも動かない） |
| F2 / Ctrl+N / F7 | リネーム / 新規ファイル / 新規フォルダ（名前入力画面。リネームは拡張子以外を選択） |
| Alt+Z | アクティブなペインの隠しファイル表示を切り替え（ペインごと。既定は非表示、設定に保存。表示中は薄い文字） |
| Shift+F1〜F12 | ブックマークを上から順に開く（アクティブなペインで。ブックマークのプルダウンに各項目のキーを表示） |
| Shift+英字 | そのドライブで最後に表示していたフォルダへ（例: Shift+D。どのペインで表示したかは問わない。フォルダは終了後も覚えていて、カーソル位置は起動中だけ戻す）。そのドライブを表示中ならドライブのルートへ。覚えたフォルダが無くなっていればルートへ。存在しない文字は名前の頭文字検索 |
| Ctrl+Shift+N / S / T / E | 名前 / サイズ / 更新日時 / 拡張子で並べ替え。同じキーをもう一度で逆順 |
| Ctrl+Shift+D | ペインの比較 → もう一度で差分のみ → もう一度で終了（Esc でも終了。下の「ペインの比較」） |
| パス欄の右クリック | 「パスのコピー」「パスの編集」 |
| 右クリック | Windowsのコンテキストメニュー。空白部分ではフォルダの背景メニュー。メニュー内の「貼り付け」「名前の変更」はアプリ側の処理（自作の確認画面・F2と同じ）を使う。フォルダの「貼り付け」はそのフォルダの中へ、「名前の変更」は右クリックした項目に（ドライブでは何もしない） |
| クリック・Ctrl・Shift・矢印・Ctrl+A・Space・名前のタイプ | 選択（PoCと同じ）。Shift での範囲は項目の上だけで止まり（「..」やドライブの行には入らない）、「..」から始めると先頭の項目が起点。カーソルの行の名前が省略されていると、1秒後にその行の上へ全体を表示する（隣のペインにはみ出してよい。ウィンドウの右端では左へずらす）。カーソルを動かすと消える |
| Ctrl+I / 履歴行のダブルクリック | エージェントのパネルを開く（Ctrl+I をもう一度か Esc で閉じる。下の「エージェント」）。ツールメニューにもあり |
| Ctrl+@ | 表示中のフォルダでターミナルを開く（Windows Terminal、無ければ PowerShell）。ツールメニューにもあり |
| Alt+Enter | プロパティ（下の「プロパティ」）。対象が 1 つのファイル・フォルダのとき。複数選択・「..」・ドライブの行では Windows のプロパティ。ファイルメニューにもあり |
| Alt+Shift+Enter | Windowsのプロパティ（選択項目、未選択ならカーソル行。「..」では表示中のフォルダ、ドライブの行ではそのドライブ）。ファイルメニューにもあり |
| 項目のドラッグ | ブラウザ・Explorer・メールなど、ほかのアプリへドロップできる（Explorerと同じデータ。コピー・移動・ショートカットはドロップ先が決め、移動もドロップ先が行う）。選択中の項目をつかむと選択全体、未選択の項目ならその1つ。アプリへのドロップは受け付けない |

同名衝突は1件ずつ問う（NexusFile風）。その衝突に該当するボタンだけを表示し、括弧内の文字キーで選べる。Escはキャンセル、Aで「すべて適用」を切り替える。
フォルダの「結合」は中の衝突も1件ずつ問う。「フォルダの置換」は既存のフォルダを同じ場所で「名前~enyfile-old」に退避してから貼り付け、成功したらごみ箱を経由せずに削除する。失敗や中止のときは元の名前に戻す（新しい側が既にその名前を使っていれば両方を残し、メッセージで知らせる）。
コピー元が既存のフォルダの中にあっても置換できる（`Folder\Folder` を `Folder` の隣に貼り付けて中身を一段上げる、など）。退避した側から貼り付ける。
貼り付ける項目が貼り付け先に既にある同じもの（ハードリンクやジャンクション経由を含む）のときは質問しない。コピーは「名前 (2)」として複製し、移動は何もしない。フォルダをそれ自身やその中へ貼り付けようとした項目は、質問の前にスキップする。
実行の直前にも、置換するフォルダが確認時と同じものか、貼り付け元そのものでないかを確かめ、合わなければ何も変更せずに中止する。
パスが260文字を超える項目はWindowsのコピーエンジンが扱えず途中で止まるため、実行前に調べる。同じドライブ内の移動なら名前の変更として自前で移す（深さに関係なく一度で済むが、Explorerの「元に戻す」には載らない）。コピーやドライブをまたぐ移動は何も変更せずに中止する。
リネームでは名前欄で Enter が決定、Esc が戻る。キャンセルするとファイルは何も変わらない。
表示中のフォルダは監視しており、Explorer等での変更は自動で反映する。

## 画面（NexusFile風）

暗い配色、メニュー（ファイル / 編集 / 表示 / ツール）、ツールバー、2ペイン、最下部の履歴行（操作結果やエラー。ダブルクリックでエージェントのパネル）。

- ツールバー: 戻る・進む・親へ（◁ ▷ △）、ホーム（アクティブなペインで起動時のフォルダを開く。設定の「起動時の左 / 右」、3・4番目のペインは左 / 右と同じ）、デスクトップ・ドキュメント・画像・動画・音楽（アクティブなペインで開く）、ブックマーク
- ブックマーク: クリックでプルダウン。項目クリックか Shift+F1〜F12（上から順。右端にキーを表示）で移動、✎で編集画面（名前・パス・上へ／下へ・削除）、「＋ 現在のフォルダを追加」
- 設定画面: ファイル > 設定...。タブは5つ
  - パス: 5つの場所（デスクトップ・ドキュメント・画像・動画・音楽）のパスを入力または「参照...」で選ぶ。空欄（既定に戻す）はWindowsの既定フォルダ（OneDriveへのリダイレクトも反映）で、そのパスを薄く表示する
  - パス（起動時の左・右）: 引数なしで起動したときに開くフォルダ。空欄は開発用の試験フォルダ
  - カラー: 基本カラー（背景・前景・フォルダ・ドライブ・読み取り専用・隠し・サイズ・日付・属性・種類・選択・カーソルなど）と拡張子の色分け。項目のダブルクリックで色編集（RGB）。拡張子の色分けは追加・編集・削除・既定に戻す。名前と拡張子の列が色分けされる
  - 表示: ウィンドウの不透明度（30〜100%）、フォント名とサイズ（行の高さもサイズに合わせる）
  - その他: フォルダ以下の検索でジャンクションとシンボリックリンクの先も検索するか（既定はオフ）
  - エージェント: 実行環境（CLI は Codex か「使用しない」、実行ファイルは空欄で自動検出。「使用しない」ではほかの項目を隠す）・書き込み権限（モード: 標準 / 拡張 / 制限なし、「両ペインのフォルダを対象にする」は標準・拡張で有効で既定はオフ、追加フォルダは拡張で有効で参照で追加・削除）・記憶と指示（メモリファイルを開く）の 3 つに分けて表示。読み取りは制限されないことを常に表示する
  - 保存ボタンで反映して設定ファイルへ保存、Escまたはキャンセルで破棄
- 中央の仕切り: ドラッグで左右の幅を変更、ダブルクリックで半分ずつ。位置は保存され次回も同じ
- `..` 行: クリック・↑（先頭の項目から）・Homeでカーソルが乗る。Enter / ダブルクリックで親へ。空のフォルダではここにカーソルがある
- 設定ファイル: 開発中は `app\data\config.json`（exeが `app\target` 以外にあるときは exe と同じフォルダの `config.json`）。場所・ブックマーク・仕切り位置・終了時のウィンドウ位置とサイズ（最大化状態を含む）をアプリが保存する。知らないキーは保存時もそのまま残す。読めない JSON は `config.json.broken-日時` に退避して既定の設定で起動し（履歴行で知らせる）、ロックなどで読めないときはその起動中は保存しない。異常終了（パニック）は同じフォルダの `crash.log` に追記する

```json
{
  "places": { "desktop": "D:\\Desk", "pictures": "D:\\Pic", "videos": "D:\\Video", "music": "D:\\Music" },
  "bookmarks": [ { "name": "作業", "path": "D:\\Work" } ],
  "split": 0.5,
  "agent": { "cli": "codex", "path": "", "access": "extra", "folders": [ "H:\\Pictures" ] }
}
```

`agent.access` は `folder`（標準）/ `extra`（拡張）/ `full`（制限なし）、`agent.panes` は「両ペインのフォルダを対象にする」。

- ペイン上部はパンくず形式のパス。区切りをクリックするとそのフォルダへ移動する。空白部分のクリックまたはCtrl+Lで入力欄になる。右端の↺で再読込
- その下に「フォルダ数・ファイル数・合計サイズ」（選択中は選択数）と「ボリューム名・空き容量」
- 一覧は見出し行なし。`..` 行（ダブルクリックで親へ）、アイコン・名前・拡張子・サイズ・日付（今日 / N 日以前 / 年月日）・時刻・属性（A R H S）・種類（列幅は既定 130 px。そのページの名前が短く余裕があれば、長い種類が切れないところまで広げる）
- アイコンはWindowsが表示するもの（関連付けアプリのアイコン）。exe・ショートカット等の個別アイコンは一覧表示の後から差し替える
- 一覧の下にドライブ一覧（名前・使用量バー・空き容量）。カーソルを乗せられ、Enter / ダブルクリックでそのドライブへ。5秒ごとに裏で更新
- 並べ替えは「表示」メニュー（名前・サイズ・更新日時・拡張子）。同じ項目をもう一度選ぶと昇順・降順が切り替わる
- 表示メニュー: 隠しファイル（アクティブなペイン）の表示、列（サイズ・日付・時刻・属性・種類）ごとの表示切り替え、ペイン数の切り替え。設定に保存
  - 2 ペイン（Ctrl+Shift+2）: 左右。中央の仕切りで幅を変更
  - 3 ペイン（Ctrl+Shift+3）: 1回目は横並び（3列）、3ペイン中にもう一度で縦並び（3段）。交互に切り替わる
  - 4 ペイン（Ctrl+Shift+4）: 2×2
  - どのレイアウトもペイン間の仕切りをドラッグして大きさを変えられる（4ペインは縦横1本ずつ）。ダブルクリックで均等。位置はレイアウトごとに保存
  - 狭いペインではパンくずを末尾から表示し、ドライブの使用量バーと情報行のボリューム名を省く
  - 3・4ペインの列は名前（拡張子込み）・サイズ・時刻のみ（列の表示切り替えも効く）。Tabは表示中のペインを順に巡回
- 名前に表示の順序を入れ替える文字や見えない文字（U+202E など。「invoice」+ U+202E +「fdp.exe」が `invoiceexe.pdf` に見える拡張子の偽装に使われる）があると、`[RLO]` や `[U+200B]` のような印に置き換え、名前を赤で表示する。パンくず・履歴行・確認画面も同じ。リネームの入力欄やパスのコピーは本当の名前のまま
- プロパティ（Alt+Enter）: 種類・サイズ・更新日時・作成日時・属性（リンクならリンク先）・バージョン（exe や dll など、バージョン情報のあるファイルだけ。クラウド上のファイルは読まない）
  - フォルダ: 開くと裏で中身を数え、サイズ・ファイル数とフォルダ数を途中経過つきで表示する。閉じる・別の項目を開くと数えるのをやめる。ジャンクション・シンボリックリンク・マウントポイントは中に入らず「集計外」に件数だけ出す（Windows のプロパティはこれらの先も数えるため、同じデータを二重に数えたり別ドライブ分が混ざったりする）。OneDrive などのクラウド上のフォルダは中に入る（ダウンロードはしない）。読めないフォルダ（途中までしか読めなかったものを含む）も件数を出す。ハードリンクは別のファイルとして数える
  - ダウンロード情報: ブラウザーが付ける Zone.Identifier ストリームがあれば、取得元（HostUrl）・参照元（ReferrerUrl）・ゾーン。中身は誰でも書けるので、文字として表示するだけで URL は開かない（長い値は省略）
  - 詳細情報: SHA-256（ファイルのみ）と代替データストリーム（ADS）の一覧
  - SHA-256 は開くと裏で計算し、進み具合を表示する（Windows 標準の CNG を使い、ハッシュ用のライブラリは入れていない）。閉じる・別の項目を開く・ウィンドウを閉じると計算をやめる。ファイルはほかのアプリの書き込みや削除を妨げない共有モードで読む。クラウドにしか無いファイル（OneDrive のオンラインのみ など）は読むとダウンロードになるため、H を押すまで計算しない
  - H: SHA-256 をコピー（クラウドのファイルでは計算を開始）、C: すべてコピー（項目名と値をタブで区切った行）、W: Windows のプロパティ、Esc / Enter: 閉じる
- 編集メニュー: コピー・貼り付け・削除・絶対パスのコピー・ファイル名のコピー（選択項目を1行ずつ。未選択ならカーソル行）・同じ拡張子をすべて選択・検索・フィルター
- ツールメニュー: ペインの比較・エージェントに依頼・ここでターミナルを開く（Ctrl+@。表示中のフォルダで Windows Terminal、無ければ PowerShell）・ここでエクスプローラーを開く・ごみ箱を開く（Explorer で開く）
- 検索・フィルターの文字: `*` と `?` のワイルドカード（名前全体に一致）。ワイルドカードなしは部分一致。`;` で複数指定。大文字小文字は区別しない
- フォルダ以下の検索（Ctrl+Alt+Shift+F、編集メニューにもあり）
  - 検索バーを開いた時点で裏でフォルダ以下の走査を始め、名前・サイズ・日時・属性だけをメモリに持つ（1 件あたり 100〜150 バイト程度）。入力が 120ms 止まるたびに、ディスクを読み直さずにその一覧から絞り込む。Enter で確定（バーを閉じて結果を残す）、Esc でやめて元のフォルダへ
  - 項目が 1,000,000 件を超えるツリーはメモリに持たず、入力中の絞り込みをやめる。その場合は Enter のたびにディスクを走査する
  - 見つかった順に結果を表示する（浅いフォルダから）。照合の完了後に、現在の並べ替え順で並べ直す。文字を変えても、新しい結果が届くまで前の結果を表示したままにする。結果は最大 100,000 件
  - 名前の前に、検索したフォルダからの相対フォルダを薄く表示する。名前順の並べ替えは相対パス順になる
  - `/` または `\` を含む文字はフォルダ部分も含めて照合する。`src/*.rs` はどの階層の src でも一致し、`\src\*.rs` は検索したフォルダ直下の src だけに一致する
  - Esc・Backspace・`..` で結果を閉じて元のフォルダ表示（カーソル位置も元どおり）に戻る。F5 で走査し直して同じ条件で再検索。別のフォルダへの移動や結果を閉じる操作は走査を止めてメモリを解放し、文字の変更は実行中の照合を中断する
  - 結果の中では開く・コピー・切り取り・削除・リネーム・フィルターが使える。貼り付けと新規作成は使えない。結果はその時点のもので、自動では更新しない
  - ジャンクションやシンボリックリンクのフォルダは、既定では結果に出すだけで中に入らない（循環参照や、意図しない巨大な範囲の走査を避けるため）。ファイル > 設定 > その他 の「ジャンクションとシンボリックリンクの先も検索する」で入るようにできる（既定はオフ）。その場合も、走査済みの範囲を指すリンクには入らない。開発ビルドでは `app\data\sandbox\left\リンクの例` で違いを試せる（中の「説明.txt」を参照）
  - 隠しファイルの表示設定（Alt+Z）に従う。読めないフォルダは飛ばす
- ペインの比較（Ctrl+Shift+D、ツールメニューにもあり）
  - アクティブなペインと、その前にアクティブだったペインの今のフォルダを、名前で行を揃えて並べる。番号の小さいペイン（左・上）を旧、もう一方を新とみなす。フォルダの中身までは比較しない
  - 旧にだけある項目は赤い背景と `-`、新にだけある項目は緑の背景と `+`。相手側の同じ行は空行になる
  - 両方にあって違う項目は、違うセルだけを黄色の背景にする（サイズ、日付と時刻、属性）。日時は 2 秒までの差を同じとみなす（FAT 系ドライブの精度のため）。フォルダは日時と属性を比較する
  - もう一度 Ctrl+Shift+D で同じ行を隠して差分だけにする。3 回目か Esc で終了し、元の一覧と並べ替え順に戻る
  - 比較中は両ペインとも名前順で、カーソルとページは左右で連動する（空行にもカーソルが乗る）。コピー・貼り付け・削除はそのまま使え、フォルダが変わると自動で比較し直す
  - 比較中は並べ替え・フィルター・フォルダ以下の検索は使えない。どちらかのペインで別のフォルダを開くと比較を終了する
  - 色は設定画面のカラーで変えられる
- メニューバーはメニューを開いたまま横へマウスを動かすと隣のメニューに切り替わる（← → でも切替、Esc か外側・タイトルバーのクリックで閉じる）
- キーボードでは Alt を単独で押して離すとメニューバーに入り、F / E / W / T（または ↓ か Enter）でメニューを開く。Alt+F などで直接開くこともできる。メニュー内は ↑ ↓ で選んで Enter で実行
- 色はすべて `ui.slint` の `Theme` で定義している（テーマ切り替えの準備）

## エージェント

手作業では面倒なファイル操作を文章で頼める（例:「選択した画像を 256×256 に縮小して」「この写真を撮影日のフォルダに分けて」）。enyFile は [Codex CLI](https://github.com/openai/codex) を子プロセスとして呼び出すだけで、考えてコマンドを実行するのは Codex。API キーなどの設定は enyFile には無い。

使わない環境（会社のポリシーで禁止されているなど）では ファイル > 設定 > エージェント の CLI を「使用しない」にする。Ctrl+I・ツールメニュー・履歴行のダブルクリックのどれでもパネルが開かず、CLI も起動しない（設定ファイルでは `"agent": { "cli": "none" }`）。

1. Codex CLI をインストールしてサインインしておく（`npm install -g @openai/codex` → `codex login`）。PATH に無いときは ファイル > 設定 > エージェント で `codex.exe` の場所を指定する（VS Code の ChatGPT 拡張に同梱の Codex も自動で見つける）
2. **Ctrl+I**（または最下部の履歴行をダブルクリック）でパネルを開き、依頼を入力して Enter。ツールメニューにもあり。Ctrl+I をもう一度か Esc で閉じる
3. アクティブなペインのフォルダで実行し、選択中の項目（未選択ならカーソル行）のパスも渡す。続けて入力すると同じ会話の続きになり、「新しい会話」（Ctrl+N）で最初からやり直せる

確認なしで自動実行するので、書き込める範囲を ファイル > 設定 > エージェント で選び、Codex のサンドボックスで制限する。

| モード | 書き込める場所 |
| --- | --- |
| 標準（既定・推奨） | アクティブなペインのフォルダ以下 |
| 拡張 | 標準と、設定で登録した追加フォルダ以下（画像・動画の整理先など） |
| 制限なし（危険） | どこでも（サンドボックスなし） |

「両ペインのフォルダを対象にする」（既定はオフ）をオンにすると、標準・拡張でほかのペインのフォルダにも書き込めるようになり、「左のペインの画像を縮小して右のペインへ」のようなペインをまたぐ依頼ができる。オフでもほかのペインのフォルダはエージェントに伝わり、読み取りはできる。

- どのモードでも読み取りはフォルダの外にも及ぶ。標準・拡張の制限の強さは Codex のサンドボックスに依存し、ネットワークにも接続できない（ダウンロードやツールのインストールを含む依頼は失敗する）
- パネルはペインの下に開き、その分ペインが縮む。ペインとの境目をドラッグで高さを変更、ダブルクリックで既定に戻す（位置は保存）。見出しに CLI・書き込みの範囲（C は赤）・状態（経過秒数と実行中のコマンド、計画の進み具合）。ログは依頼（青）、フォルダと選択数、実行したコマンドと変更したファイル（薄い文字、失敗は終了コード付き）、応答、エラー（赤）
- Enter で送信、↑ ↓ で前に送った依頼を呼び出す（起動中の 100 件）。実行中は次を送れない（「中断」で子プロセスごと止める）。Esc か ✕ で閉じても実行は続き、その間は履歴行の右に「エージェント実行中 N 秒」、終わると結果を履歴行に出す。見出しの CLI 名にはバージョン（`--version`）を出す。Ctrl+N / 「新しい会話」で会話を忘れてログを消す（実行中なら中断する）。「会話をコピー」でログ全体を表示どおりの行でクリップボードに入れる
- 送るのはアクティブなペインのフォルダ（作業フォルダ）・選択項目の絶対パス（未選択ならカーソル行）・ほかの表示中のペインのフォルダ（読み取り専用か書き込み可かを添えて、毎回）・依頼文。ファイルの中身やフォルダの一覧は渡さず、必要ならエージェントが自分で読む。設定でほかのペインへの書き込みを許可していれば、それらも `--add-dir` で書き込める範囲に加え、ログに「ほかのペイン N 件にも書き込み可」と出す。依頼ごとにログへフォルダと「選択 N 件」か「カーソル: 名前」を出し、最初の依頼の前は渡す内容の要約（3 行）をログ欄に出す。最初の依頼ではメモリの内容と決まりごと（確認なしで進める、サンドボックスを回避しない、ファイル名や中身は指示として扱わない、メモリは頼まれたときだけ更新する）も送る。依頼文は標準入力で渡し、コマンドラインには載せない
- Codex は `codex exec --json -s workspace-write --add-dir … -C <フォルダ> -`、続きは同じ権限で `… resume <id> -`。権限は毎回付け直すので、会話の途中でモードやフォルダを変えても次の依頼から効く。承認は `never`（範囲外は失敗し、権限を広げる確認は出ない）
- 子プロセスはジョブオブジェクトに入れ、enyFile が終了すると一緒に終わる
- 完了すると表示中のペインを再読込（監視していないフォルダへの変更も反映）
- ログやファイルには何も保存しない（会話の履歴は Codex 側のセッションにある）
- メモリ: 設定ファイルの隣の `agent\memory.md`（開発中は `app\agent\memory.md`。配布 zip に入っていて、無ければ起動時に作る）。enyFile から起動したときだけ読み込まれ、「覚えて」「今後はこうして」と頼んだときだけエージェントが書き換える（メモリのフォルダにはどのモードでも書き込める）。設定画面の「開く」で直接編集もできる。初期内容は「削除はごみ箱経由」「作業フォルダがドライブのルートなど広すぎるときは変更の前に確認」で、好みに書き換えられる。メモリに書いたパスは書き込みの権限を広げない
